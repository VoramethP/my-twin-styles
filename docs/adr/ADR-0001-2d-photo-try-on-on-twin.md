# ADR-0001 — ลองชุดด้วย AI แบบ 2D บนรูปถ่ายจริงของผู้ใช้ (twin)

**สถานะ:** ✅ Accepted · 2026-09-19

## บริบท

แกนของแอปคือ "ลองชุดก่อนแต่ง" เพื่อเก็บไว้เป็น ref การตัดสินใจนี้กำหนดทุกอย่างถัดไป:
ผู้ใช้ต้องให้ข้อมูลอะไร ต้นทุนต่อครั้งเท่าไหร่ และผลดูสมจริงแค่ไหน

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| Mix & match แบบ flat-lay (วางรูปชิ้นต่อกัน) | ถูก เร็ว ไม่ต้องใช้ AI | ไม่เห็นว่าใส่บนตัวเองแล้วเป็นยังไง — ไม่ตอบโจทย์ |
| Avatar 3D จากสัดส่วนร่างกาย | หมุนดูได้ | ทำยาก ผลดูไม่เป็นธรรมชาติ ต้องมีโมเดล 3D ของทุกชิ้น |
| **AI try-on 2D บนรูปถ่ายจริงหลายท่า (twin)** ✔︎ | สมจริงที่สุดจากรูปธรรมดา ใช้ API ที่มีอยู่ได้ | มีค่าใช้จ่ายต่อครั้ง ช้า 10–40 วิ รองเท้า/accessory ยังไม่เสถียร |

## การตัดสินใจ

ผู้ใช้สร้าง twin จากรูปเต็มตัว 1–5 ท่า แล้วลองทั้งชุดในครั้งเดียวตามช่อง
(เสื้อ · ท่อนล่าง · ชั้นนอก · หรือเดรส) ผลที่สำเร็จกลายเป็นลุคใน lookbook
รองเท้า กระเป๋า เครื่องประดับเป็น "ส่วนประกอบ" แนบดูคู่กัน ไม่ render ลงตัว

## ผลที่ตามมา

- ต้องมีการเช็กคุณภาพรูปท่า: บล็อก (ไม่เต็มตัว · หลายคน · รูปเล็ก) / เตือน (มืด · พื้นหลังรก · ชุดหลวม)
- การลองต้องทำงานเบื้องหลัง (async) + แจ้งเตือน เพราะช้าเกินกว่าจะให้รอหน้าเดิม
- ต้นทุนต่อครั้ง → ต้องมีโควต้า (ดู [ADR-0002](ADR-0002-open-signup-with-quota-and-global-cap.md))
- ผู้ให้บริการ AI ยังไม่เลือก — ต้องห่อไว้หลัง interface เดียวให้เปลี่ยนเจ้าได้

## ทบทวนเมื่อไหร่

เมื่อโมเดล try-on render รองเท้า/accessory ได้เสถียร หรือเมื่อต้นทุนต่อครั้งเปลี่ยนมากจนกระทบโควต้า
